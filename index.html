02 / UNDERSTAND THE RULES

From code to something you hear.

An algorithm is a set of instructions. Here it chooses when a note happens, how high it is, and how long it lasts.

How the whole composition works, in ordinary language

First, build a list of timed notes. At 120 beats per minute, each beat lasts half a second; each half-beat slot lasts a quarter of a second. Sixty seconds contains 240 slots. The score chooses which slots contain notes and which contain silence.

Each note stores its time, duration, frequency, waveform and gain. Melody is the higher line. Bass supplies a lower reference. Pulse is a short, low tone marking a rhythm. Small fades at the beginning and end of each note reduce abrupt clicks.

For the final version, the slot number also chooses a 15-second section. Each section changes the density, register or waveform. The score is generated before playback, then scheduled using the browser's audio clock. A slow visual frame cannot change the intended note timing.

The algorithm does not use random numbers or noise. Its fixed arrays and arithmetic produce the same note list on every replay, without needing randomSeed() or noiseSeed(). If you add randomness in p5, use randomSeed(0) and noiseSeed(0), as the assignment requests.

The p5 download uses noCanvas() and noLoop() for the audio-only presentation. Its sound engine uses the browser's native Web Audio oscillators. This makes a computational composition rather than a recording played unchanged.

Make it your own: three small, testable changes
  1. In composer.js (or the engine at the top of the downloaded sketch), change one entry in the pitch-ratio or melody array. Replay and describe the changed note.
  2. Change one rhythm condition. For example, an event every fourth slot becomes every eighth slot. Count the events and hear the wider spacing.
  3. Change a section's waveform or gain. Keep the note timings the same, so you compare sound character independently of rhythm.

The code snippets above explain the ideas. The downloaded sketch contains the complete working implementation. After changing the rules, rebuild your score and repeat the timed listening process.
